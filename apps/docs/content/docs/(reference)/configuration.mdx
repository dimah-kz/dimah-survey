Fill and editor have separate configuration types because they expose different
trust boundaries. Both require the same `database`; only fill accepts response
validation and only editor accepts publish hooks.

## Fill instance

```ts
import { dimahSurvey, guardAnonymous } from "@dimah-survey/server";

import { database } from "@/db";

export const fill = dimahSurvey({
  audience: "fill",
  database,
  guard: guardAnonymous(),
});
```

[Database](/docs/persistence) creates `database` with `@dimah-survey/db`.

`checkSurveyResult` drops values that cannot be assigned, runs `validate`, and
returns the `survey.data` to persist. Questions with `choicesByUrl` keep their
posted value. The server does not fetch that list.

A custom `validateResult` receives `{ definition, data }`. Return the object to
store. Return nothing to keep `data`. Throw `APIError` with `VALIDATION_FAILED`
to reject the submit. See [Responses](/docs/responses).

Returning nothing from a fill guard is forbidden. `guardRespondent(id)` returns
`{ respondentId }`. `guardAnonymous()` returns `{ anonymous: true }`.


A start that returns an existing row does not call `onStart` or `afterStart`.
A replayed submit does not call `onSubmit` or `afterSubmit`. The HTTP body
cannot carry these hooks.

## Frequently asked questions

<Accordions>

<Accordion title="Why can't the editor configure validateResult?">

Submit validation runs on the fill audience, against the response snapshot.
Publish hooks run on the editor audience. Each config type exposes only the
callbacks for its trust boundary.

</Accordion>

<Accordion title="What should validateResult return?">

Return the object to persist. Return nothing to keep the submitted `data`.
Throw `APIError` with `VALIDATION_FAILED` to reject the submit. The callback
still receives the stored `definition`. The HTTP body cannot replace it.

</Accordion>

<Accordion title="Why did onStart not run?">

`onStart` and `afterStart` run only before a new insert. A start that returns
an existing identified response skips them. An idempotent resubmit skips
`onSubmit` and `afterSubmit` as well.

</Accordion>

</Accordions>
