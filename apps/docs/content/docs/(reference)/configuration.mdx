Fill and editor have separate configuration types because they expose different
trust boundaries. Both require the same `database`; only fill accepts response
validation and only editor accepts publish hooks.

## Fill instance

```ts
import {
  dimahSurvey,
  guardAnonymous,
  memoryAdapter,
} from "@dimah-survey/server";

export const fill = dimahSurvey({
  audience: "fill",
  database: memoryAdapter(),
  guard: guardAnonymous(),
});
```

| Option            | Required | Default             | Purpose                                                |
| ----------------- | -------- | ------------------- | ------------------------------------------------------ |
| `audience`        | Yes      | —                   | Must be `"fill"`                                       |
| `database`        | Yes      | —                   | Shared `SurveyStore`                                   |
| `guard`           | Yes      | —                   | Return an identified or anonymous principal, or throw  |
| `basePath`        | No       | `"/api/survey"`     | Must match the fill client `baseURL`                   |
| `hooks`           | No       | —                   | `onStart`, `afterStart`, `onSubmit`, and `afterSubmit` |
| `sanitizePartial` | No       | `"clear"`           | Clear values invalid for the snapshot or store as sent |
| `validateResult`  | No       | `checkSurveyResult` | Validate and normalize submit data                     |

`checkSurveyResult` drops values that cannot be assigned, runs `validate`, and
returns the `survey.data` to persist. Questions with `choicesByUrl` keep their
posted value. The server does not fetch that list.

A custom `validateResult` receives `{ definition, data }`. Return the object to
store. Return nothing to keep `data`. Throw `APIError` with `VALIDATION_FAILED`
to reject the submit. See [Responses](/docs/responses).

### Lifecycle hooks

| Hook          | Timing                                       | If it throws         |
| ------------- | -------------------------------------------- | -------------------- |
| `onStart`     | Inside the store lock, before a new insert   | Abort the insert     |
| `afterStart`  | After the insert, still inside the lock      | Leave the row stored |
| `onSubmit`    | After validation, before the submitted write | Abort the write      |
| `afterSubmit` | After the submitted row is stored            | Leave the row stored |

A start that returns an existing row does not call `onStart` or `afterStart`.
A replayed submit does not call `onSubmit` or `afterSubmit`. The HTTP body
cannot carry these hooks.

## Editor instance

```ts
import { dimahSurvey } from "@dimah-survey/server";

export const editor = dimahSurvey({
  audience: "editor",
  database,
});
```

| Option     | Required | Default               | Purpose                                         |
| ---------- | -------- | --------------------- | ----------------------------------------------- |
| `audience` | Yes      | —                     | Must be `"editor"`                              |
| `database` | Yes      | —                     | Same store used by fill                         |
| `guard`    | No       | Allow                 | Return nothing or throw; principals are invalid |
| `basePath` | No       | `"/api/admin/survey"` | Must match the editor client `baseURL`          |
| `hooks`    | No       | —                     | `onPublish` and `afterPublish`                  |

| Hook           | Timing                            | If it throws         |
| -------------- | --------------------------------- | -------------------- |
| `onPublish`    | Before `draftJson` is promoted    | Abort the write      |
| `afterPublish` | After the published row is stored | Leave the row stored |

`resumeSurvey` does not call publish hooks.

## Browser clients

`createFillClient` and `createEditorClient` accept:

| Option        | Purpose                                                       |
| ------------- | ------------------------------------------------------------- |
| `baseURL`     | Fill defaults to `/api/survey`; editor to `/api/admin/survey` |
| `credentials` | Forwarded to `fetch`; use `"include"` for cross-site cookies  |
| `headers`     | Static `HeadersInit` or a function that returns headers       |
| `fetch`       | Replace the global fetch implementation                       |

Browser methods take flat objects. `fill.api` and `editor.api` take `{ body }`
or `{ query }`, plus optional `headers` or `request` for guards. See
[Mount the server](/docs/integration).

## React

`useSurveyResponse({ client, responseId, partial })`

| Option       | Default  | Purpose                                                 |
| ------------ | -------- | ------------------------------------------------------- |
| `client`     | —        | Fill client used for load, partial save, and submit     |
| `responseId` | —        | Response row to hydrate                                 |
| `partial`    | `"page"` | Save on page next, or `"off"` to write only on complete |

Returned fields are documented in [React](/docs/react).

`useSurveyDraft({ client, surveyId, creator, updatedAt })`

| Option      | Purpose                                                  |
| ----------- | -------------------------------------------------------- |
| `client`    | Editor client used for `saveSurvey`                      |
| `surveyId`  | Draft to write                                           |
| `creator`   | Existing Creator instance; `null` skips binding          |
| `updatedAt` | Compare-and-swap token from the read that loaded Creator |

The hook does not construct Creator. See [Creator](/docs/creator).
