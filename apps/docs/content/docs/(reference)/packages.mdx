The four packages version together but keep runtime boundaries separate. Most
React applications use `server`, `db`, and `react`.

<Callout>
  Published on npm, still before `1.0.0`. A release may change the API.
</Callout>

| Package                | Responsibility                                                |
| ---------------------- | ------------------------------------------------------------- |
| `@dimah-survey/core`   | Protocol types, browser clients, schemas, and store contracts |
| `@dimah-survey/server` | Handlers, guards, validation, and runtime adapters            |
| `@dimah-survey/react`  | SurveyJS `Model` and Creator lifecycle bindings               |
| `@dimah-survey/db`     | FumaDB-backed SQL store and schema references                 |

```npm
npm i @dimah-survey/server @dimah-survey/db @dimah-survey/react react react-dom survey-core survey-react-ui
```

[Database](/docs/database) installs `fumadb` and adds the tables to Drizzle,
Prisma, or Kysely. Install `survey-creator-core` and `survey-creator-react`
only when you render Creator.

## `@dimah-survey/server`

Backend integration:

- `dimahSurvey()` for fill and editor instances
- `memoryAdapter()` for a process-local store
- `guardRespondent()` and `guardAnonymous()` for fill guards
- `checkSurveyResult()` for submit validation
- `clearSurveyResult()` for partial-save sanitization
- adapters for Next.js, Node, Express, Hono, Fastify, Elysia, and SvelteKit

Browser bundles should import clients from `react` or `core`, not `server`.

## `@dimah-survey/react`

React client code:

- `useSurveyResponse()` and `bindSurveyModel()` for fill sessions
- `useSurveyDraft()` and `bindSurveyCreator()` for Creator autosave
- `isStaleUpdate()` for write-state handling
- `createFillClient()` and `createEditorClient()` from `core`

It requires React and `survey-core` as peers. Your application imports
`survey-react-ui` and `survey-creator-react`, constructs their objects, and
renders their components.

## `@dimah-survey/core`

Use `core` for non-React clients, shared protocol code, or custom stores. It
contains clients, route constants, Zod schemas, stable error codes, helpers,
and `SurveyStore` types.

Most applications use `createFillClient()` or `createEditorClient()`. Reach
for `createSurveyFetch()` only when you need the lower-level better-fetch
surface.

## `@dimah-survey/db`

`db(client)` adapts a FumaDB client to `SurveyStore`. `DimahSurveyDB` describes
the versioned schema; Drizzle, SQL, and Prisma exports are readable reference
files.

<Callout type="warn">
  Copy or generate those schema references into your application, then migrate
  the application-owned file. Do not import a reference schema into a running
  application.
</Callout>

`memoryAdapter()` keeps rows in the process for tests. `@dimah-survey/db` is
the SQL store. A custom `SurveyStore` is the alternative when those tables
cannot live in your database. See [Database](/docs/database). Every store
must preserve immutable response definitions, compare-and-swap inside writes,
and one open draft per identified respondent.

Continue with [Configuration](/docs/configuration) or the
[HTTP protocol](/docs/protocol).
