The repository includes a working Next.js application that connects the four
packages end to end. SurveyJS renders the form and Creator; dimah-survey owns
publish, response snapshots, drafts, and submit validation.

<Callout>
  The example is the canonical integration reference, not an application
  template. Copy the boundaries you need and replace its open editor guard with
  your own authorization.
</Callout>

## Run it

From the repository root:

```bash
pnpm install
pnpm example
```

Open [http://localhost:3000](http://localhost:3000). The app creates a local
SQLite database at `examples/next/data/survey.db` and seeds a welcome survey.

## Follow the complete lifecycle

| Route                          | What to inspect                                   |
| ------------------------------ | ------------------------------------------------- |
| `/`                            | Published surveys and the respondent's open draft |
| `/r/[responseId]`              | Partial save, submit, abandon, and reopen         |
| `/studio`                      | Survey creation, publish, archive, and status     |
| `/studio/[surveyId]`           | Creator autosave with an explicit publish action  |
| `/studio/[surveyId]/responses` | Response summaries and stored snapshots           |

The fill API is mounted at `/api/survey`. The editor API is mounted separately
at `/api/admin/survey`.

## Read the integration by boundary

- [`lib/survey.ts`](https://github.com/dimah-kz/dimah-survey/blob/main/examples/next/lib/survey.ts)
  creates the shared SQL store and the fill/editor instances.
- [`lib/clients.ts`](https://github.com/dimah-kz/dimah-survey/blob/main/examples/next/lib/clients.ts)
  creates browser clients with matching base paths.
- [`components/fill-survey.tsx`](https://github.com/dimah-kz/dimah-survey/blob/main/examples/next/components/fill-survey.tsx)
  renders the response snapshot and handles stale writes.
- [`components/survey-designer.tsx`](https://github.com/dimah-kz/dimah-survey/blob/main/examples/next/components/survey-designer.tsx)
  binds Creator autosave while keeping publish explicit.
- [`db/schema.ts`](https://github.com/dimah-kz/dimah-survey/blob/main/examples/next/db/schema.ts)
  shows the application-owned Drizzle schema and indexes.

The respondent identity comes from an httpOnly cookie. Missing cookies use an
anonymous principal; identified requests resume the respondent's open draft.
The Studio is intentionally unguarded so the demo can run without an auth
provider.

## Quickstart or example?

Use the [Quickstart](/docs/quickstart) to understand the smallest working
integration. Use this application when you need the durable store, real route
layout, Creator workflow, response lists, or production-shaped error states.

Continue with [Security](/docs/security) before exposing the editor route, then
read [Persistence](/docs/persistence) to adapt the schema to your database.
