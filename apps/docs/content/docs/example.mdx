The [Next.js example](https://github.com/dimah-kz/dimah-survey/tree/main/examples/next)
is the complete reference integration. It uses SQLite, Drizzle, both HTTP
audiences, Survey Creator, and the SurveyJS renderer.

<Callout>
  The example intentionally leaves the editor unguarded so you can explore the
  workflow. Add an editor guard before using the same pattern in an application.
</Callout>

## Start it

From the repository root:

```bash
pnpm install
pnpm example
```

The app applies its local migrations and seeds a published `welcome` survey on
startup. Open the URL printed by Next.js.

## Follow one survey

| Path                           | What it demonstrates                                                       |
| ------------------------------ | -------------------------------------------------------------------------- |
| `/`                            | Lists active surveys and starts or continues a respondent's draft          |
| `/r/[responseId]`              | Renders a response snapshot, saves by page, submits, abandons, and reopens |
| `/studio`                      | Creates surveys and manages their published state                          |
| `/studio/[surveyId]`           | Autosaves the Creator draft; publish remains an explicit action            |
| `/studio/[surveyId]/responses` | Reads stored response snapshots through the editor audience                |

The example keeps an httpOnly respondent cookie. An identified respondent
therefore continues their open draft under the default `"one-open"` policy.
Visitors without that cookie follow the anonymous capability model instead.

## Read the integration in order

1. [`lib/survey.ts`](https://github.com/dimah-kz/dimah-survey/blob/main/examples/next/lib/survey.ts)
   creates one SQL store and passes it to separate fill and editor instances.
2. [`app/api/survey/[[...path]]/route.ts`](https://github.com/dimah-kz/dimah-survey/blob/main/examples/next/app/api/survey/%5B%5B...path%5D%5D/route.ts)
   and the matching admin route mount the two handlers.
3. [`components/fill-survey.tsx`](https://github.com/dimah-kz/dimah-survey/blob/main/examples/next/components/fill-survey.tsx)
   binds a `Model` to partial save and submit.
4. [`components/survey-designer.tsx`](https://github.com/dimah-kz/dimah-survey/blob/main/examples/next/components/survey-designer.tsx)
   binds Creator autosave to `draftJson` and publishes separately.
5. [`db/schema.ts`](https://github.com/dimah-kz/dimah-survey/blob/main/examples/next/db/schema.ts)
   shows the app-owned SQL schema, including the open-draft index.

## What to copy

Copy the boundary, not the demo's open editor policy:

- one shared `database`
- distinct fill and editor routes
- a server-derived respondent identity in the fill guard
- app-owned migrations and indexes
- `response.definition` plus `response.data` for analytics

For a smaller in-memory integration, continue with
[Minimal integration](/docs/quickstart). For a production-shaped server setup,
read [Integration](/docs/integration) and [Persistence](/docs/persistence).
