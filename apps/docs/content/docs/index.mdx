dimah-survey is the response lifecycle for [SurveyJS](https://surveyjs.io/) JSON.
SurveyJS owns the survey schema, the renderer, and Creator. This library owns
the editor draft, the published document, the definition copied onto each
response, drafts, and submit validation against that snapshot.

Your application owns authentication, the SurveyJS UI, and the database.

It is not a form renderer, not a hosted survey product, and not a question-type
system. Question JSON stays SurveyJS JSON.

## The model

<Flow
  label="One response"
  steps={[
    { name: "Draft", kind: "data", note: "Creator writes draftJson" },
    { name: "Publish", kind: "server", note: "Copy onto publishedJson" },
    { name: "Start", kind: "server", note: "Freeze the definition" },
    { name: "Fill", kind: "client", note: "SurveyJS renders" },
    { name: "Submit", kind: "server", note: "Validate the snapshot" },
  ]}
/>

`saveSurvey` stores `draftJson` only. `publishSurvey` copies that JSON onto
`publishedJson`. `startResponse` copies `publishedJson` into
`response.definition`. Later publishes do not change that copy.

`settings` is a third column: who may respond, whether a submitted row can
reopen, the open window, and the response cap. It is not SurveyJS JSON and it
is not copied onto `definition`.

## What you install

| Need                                     | Package                |
| ---------------------------------------- | ---------------------- |
| Server instance, handler, and adapters   | `@dimah-survey/server` |
| Model and Creator bindings               | `@dimah-survey/react`  |
| Routes, payloads, and a non-React client | `@dimah-survey/core`   |
| SQL store                                | `@dimah-survey/db`     |

`database` is required on `dimahSurvey()`. SQL is optional: use
`memoryAdapter()` for tests and local development, or `db()` from
`@dimah-survey/db` in production.

Mount two handlers that share that store. `audience: "fill"` serves start,
partial save, and submit. `audience: "editor"` serves the draft, publish, and
response lists. Neither handler serves the other audience.

`@dimah-survey/react` binds a `survey-core` `Model` and Creator autosave. It
does not render `<Survey>` or Creator. Those components stay in your app.
