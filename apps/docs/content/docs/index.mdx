dimah-survey is the server-side lifecycle for
[SurveyJS](https://surveyjs.io/) JSON. It separates the document an editor is
working on from the document a respondent actually started.

SurveyJS still owns the schema, Creator, and renderer. Your application still
owns authentication, database migrations, and UI composition. This library
owns the boundary between them: draft, publish, response snapshot, partial
save, and submit.

<Callout>
  A later publish never changes an existing `response.definition`. Submit
  validation always receives that stored definition, not the live draft.
</Callout>

## What belongs where

| Concern                                       | Owner                                         |
| --------------------------------------------- | --------------------------------------------- |
| Question JSON, `<Survey>`, Creator            | SurveyJS and your application                 |
| Auth, sessions, roles, SQL migrations         | Your application                              |
| Draft/publish boundary and response snapshots | dimah-survey                                  |
| Browser client and React bindings             | `@dimah-survey/core` or `@dimah-survey/react` |
| Durable SQL `SurveyStore`                     | `@dimah-survey/db` or your own adapter        |

The server runs two isolated audiences against one shared store:

- **Fill** starts, saves, submits, abandons, and reopens responses. It requires
  a guard that establishes the respondent.
- **Editor** edits drafts, publishes, controls collection settings, and reads
  full response snapshots.
