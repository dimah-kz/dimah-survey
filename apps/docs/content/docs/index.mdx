dimah-survey adds a server-side lifecycle to
[SurveyJS](https://surveyjs.io/) JSON. It separates authoring from publishing,
stores the exact version each response starts with, and validates submission
against that snapshot.

SurveyJS still owns the schema, Creator, and renderer. Your application owns
authentication, migrations, files, and UI.

<Callout>
  Publishing again never changes the version an existing response started on.
</Callout>

## The lifecycle

<Flow
  label="One response"
  steps={[
    { name: "Author", kind: "data", note: "Creator writes draftJson" },
    { name: "Publish", kind: "server", note: "Store an immutable version" },
    {
      name: "Start",
      kind: "server",
      note: "Point the response at that version",
    },
    { name: "Fill", kind: "client", note: "SurveyJS renders the snapshot" },
    { name: "Submit", kind: "server", note: "Validate the same snapshot" },
  ]}
/>

`draftJson` is the editor copy. Publishing stores that document as an immutable
version, or reuses the version when the canonical JSON is unchanged.
`publishedJson` on a survey read is the current version. Starting a response
stores that version id; a single-response read joins the document back as
`definition`.

## Ownership

| Owner            | Responsibility                                                    |
| ---------------- | ----------------------------------------------------------------- |
| SurveyJS         | Schema, `Model`, renderer, Creator, and question behavior         |
| Your application | Authentication, authorization, migrations, file storage, and UI   |
| dimah-survey     | Publishing, collection policy, response drafts, and submit checks |

The backend exposes two isolated audiences over one shared `SurveyStore`:

| Audience | Caller                   | Access                                                   |
| -------- | ------------------------ | -------------------------------------------------------- |
| Fill     | Respondents              | Published surveys and their own response lifecycle       |
| Editor   | Trusted application code | Drafts, publishing, settings, and complete response data |

The audiences share one `SurveyStore`, but each has its own handler and guard.
Editor operations are never mounted on the fill route.
